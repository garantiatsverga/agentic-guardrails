## Почему LLM **не** используется в спринте 1

| Место | LLM нужна? | Почему нет |
|---|---|---|
| Document Agent (извлечение) | Нет | `pdfplumber` + regex детерминированно; §7.1 спеки |
| Scoring Agent | Нет | ML-модель скоринга, не LLM |
| Compliance Agent | Нет | Правила (`HookBus`) + API (MCP) |
| Review Agent | Может быть | В документе — шаблон «объяснение для клиента»; мок честен |
| OCR сканов | Да (спринт 2) | Vision-модель; §13 спеки |
| MCP-интеграция | Да (спринт 2–3) | Function calling; §13 спеки |

**Аргумент для питча:** «LLM в спринте 1 — это **риск** 152-ФЗ (отправка данных клиента в OpenAI) и **недетерминизм** (разный JSON на одном PDF). Мы **сознательно** используем детерминированный парсинг, а LLM (OCR, MCP) — спринт 2. Это **аргумент зрелости**, а не пробел».

## Что это значит для демо

- **Кнопка «Только Document Agent»** — реальный прогон, 4 кейса §12, 36 тестов.
- **Кнопка «Полный процесс (все агенты, МОК)»** — 8 этапов, где **реально** только Document Agent + AuditChain, остальное — моки с явной пометкой `[МОК]` на странице.
- **Страница `/application/{id}`** — 12 разделов, каждый с бейджем `РЕАЛЬНО` или `МОК`. Это **ровно** «похоже на настоящий процесс», как просит коллега, и **честно** про упрощения.
